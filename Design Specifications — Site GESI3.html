Design Specifications — Site GESI3

Document de référence pour toute IA ou développeur reprenant ce projet. Couvre les 3 directions de style, leurs variantes clair/sombre, et la spécification de chaque composant.

1. Système de design : 3 directions interchangeables

Le site supporte 3 identités visuelles distinctes, sélectionnables en direct via un bouton "Style", chacune disponible en clair et sombre (6 combinaisons totales). Le contenu et la structure HTML restent identiques ; seuls les styles CSS et quelques libellés changent.

Direction Esprit Polices Cas d'usage
Zine Étudiant (défaut) Post-its, papier, décalage ludique Georgia (titres), système (corps), Courier New (métadonnées) Ambiance vie étudiante, chaleureuse
Éditorial Technique Revue/rapport, lignes strictes Georgia (titres + corps), Courier New (métadonnées) Look sobre, professionnel
Terminal / Blueprint Console, monospace Courier New (tout) Cohérent avec filière électrotechnique/systèmes

2. Palettes de couleurs

Chaque direction définit 5 variables : --paper (fond), --card (fond des blocs), --ink (texte/bordures), --accent (couleur primaire), --accent2 (couleur secondaire), --shadow (couleur des ombres portées).

Règle de bascule : la direction (data-direction sur <body>) et le mode (clair/sombre) sont indépendants — 3 × 2 = 6 rendus. Le mode par défaut suit prefers-color-scheme, avec override manuel persisté en localStorage.

3. Typographie

Rôle Variable CSS Valeur
Titres --font-head Georgia, serif (Zine, Éditorial) / 'Courier New', monospace (Terminal)
Corps --font-body -apple-system, Helvetica, Arial, sans-serif
Métadonnées (heures, dates, labels techniques) --font-meta 'Courier New', monospace (toutes directions)

Tailles de référence : logo ~1.5rem (900), titres de jour ~1.1rem (700), titre de séance ~1rem (800), métadonnées ~0.68–0.75rem, tags ~0.62rem (majuscules, 800).

4. Composants

4.1 Header

  • Logo du site : nom "GESI3", style variant par direction (badge incliné pour Zine, soulignement épais pour Éditorial, préfixe $ pour Terminal).
  • Sous-titre : établissement + semestre + année.
  • Tampon date/semaine : pastille avec bordure pointillée, affiche JJ/MM/AAAA · Semaine N, synchronisée avec la navigation de semaine.

4.2 Dock de contrôle (droite, centré verticalement sur grand écran)

  • Desktop (> 640px) : Position fixe top:50%; right:14px; transform:translateY(-50%). Conteneur arrondi (border-radius:16px) avec ombre portée dure, fond --card, bordure --ink. Le contenu garde une marge droite (~90px).
  • Mobile (≤ 640px) : Le contenu reprend sa pleine largeur centrée (marge droite normale de 16px). Le dock s'adapte sous forme de barre flottante discrète ou tiroir compact pour éviter de compresser la grille d'emploi du temps.
  • 3 boutons de direction empilés verticalement, chacun avec icône courte (Éd/Tm/Zn) + libellé complet en dessous ; le bouton actif est rempli avec --accent.
  • Séparateur fin (opacity:.2).
  • Bouton thème (icône soleil/lune + libellé "Thème") en bas du dock.

4.3 Onglets (Planning / Documents)

Libellés adaptés par direction :

Direction Onglet 1 Onglet 2
Zine 📌 Planning 📎 Documents
Éditorial 01 — Planning 02 — Documents
Terminal > planning > docs

4.4 Navigateur de semaine

  • Bandeau avec bouton ‹ / numéro de semaine / bouton › ; bornes 1 à 11.
  • Boutons circulaires (Zine/Éditorial) ou carrés arrondis (Terminal).

4.5 Carte de séance

Composant central du planning, avec 3 variantes visuelles selon la direction (même structure HTML : heure, nom du module, tag(s)) :

  • Zine : "post-it" — fond --card, bordure 2px --ink, ombre dure décalée, légère rotation aléatoire (±1–1.2deg), petit ruban "washi tape" décoratif en haut.
  • Éditorial : ligne de tableau — pas de rotation ni d'ombre, bordure gauche 4px --accent, séparateur bas 1px, pas de washi tape.
  • Terminal : bloc console — bordure 1px --accent2, coins arrondis 4px, préfixe > devant l'heure, police monospace.

4.6 Tags de séance et états de report / annulation

Badge coloré (fond plein, texte blanc, majuscules, arrondi 3px) :

  • Type régulier : Cours, TD, Cours+TD, TP, Activité Pratique.
  • Séance reportée : fond --accent avec mention Reporté en Semaine [N] (et date si connue).
  • Séance annulée : fond rouge sombre avec mention Séance Annulée.
  • Séance de rattrapage injectée : badge Rattrapage (Semaine [N]).

4.7 Chips de matière

  • Affichées toutes en même temps, sans défilement horizontal (flex-wrap:wrap, pas de scroll).
  • Libellés = noms regroupés par module parent (Smart Grids, Véhicule, Énergie Multisources, Confort / Dimensionnement, Langues, Management, Audit Énergétique).
  • Chip active : fond --accent, texte blanc.

4.8 Filtres de documents

Petits chips pilule (border-radius:999px) : Tous / Cours / TD / Correction TD / TP / Autre. Actif = fond --ink, texte --paper.

4.9 Carte de document

Même logique de variantes que la carte de séance (post-it / ligne éditoriale / bloc terminal). Contenu : tag, titre, métadonnées (type de fichier, taille, date d'ajout), lien de téléchargement direct.

5. Interactions et état

  • Changement de direction : instantané, purement CSS (variables + attribut data-direction), pas de rechargement.
  • Changement de thème clair/sombre : bascule mode, persisté dans localStorage, valeur par défaut = préférence système.
  • Navigation semaine : état JS simple (week, borné 1–11), répercuté sur le tampon d'en-tête et le bandeau de navigation.
  • Sélection de matière / filtre de tag : état visuel réactif connecté aux tables Supabase modules et documents.

6. Accessibilité et responsive

  • Cible principale : mobile, layout en une colonne, max-width:640px centré.
  • Sur mobile (écran ≤ 640px) : retrait du padding-right forcé de 90px pour garder l'espace de lecture optimal.
  • Respect des zones sûres iOS (env(safe-area-inset-*)).
  • Contraste : chaque palette a été choisie pour garder --ink sur --paper/--card lisible en clair et en sombre.
  • Tous les boutons de contrôle ont un title explicite pour les lecteurs d'écran.

7. Connexion aux données réelles

Cette spécification est branchée sur le modèle de données finalisé défini dans technique.md et le script supabase_setup.sql :

  • Table modules : gestion des parents (ex: M354 regroupant Confort et Dimensionnement) pour les chips.
  • Table sessions : emploi du temps officiel S1..S11 (cours, td, tp, ap, groupes Gr1/Gr2).
  • Table reports : gestion des reports avec new_week et support des annulations (status in ('reported', 'cancelled')).
  • Table documents : fichiers partagés avec file_path synchronisé avec le bucket Supabase Storage pour suppression complète.
